# mercurius-mcp-gemini-api

## Назначение и границы

MCP-сервер по stdio: инструменты медиа и фоновых агентов Google по ключу Gemini API. Это модуль Меркурия (сабмодуль
`mcp/gemini-api`, имя установки — `gemini-api`): идёт в поставке, ставится в песочницу, запись `.mcp.json` несёт ключ секретом. Сервер не делает
запросов к Google сам: каждый вызов инструмента — один запуск официального клиента
[gemini-api-cli](https://github.com/google-gemini/gemini-api-cli) закреплённой версии. Что вызову можно и сколько он
стоит, сервер не решает: классы инструментов по пометкам и карточки подтверждения — в ядре Меркурия.

К подписке Google сервер отношения не имеет: клиент работает только по ключу, каждый вызов оплачивается по прайсу API.

## Устройство

- `bin/gemini-api-mcp` — запуск; из окружения: `GEMINI_API_KEY`, `GEMINI_API_BIN` (другой бинарь или команда с
  первыми аргументами — для проверок), `GEMINI_API_TIMEOUT` (секунд на один запуск бинаря, по умолчанию 100, не
  больше 900).
- `bin/fetch-binary` — шаг после `composer install` (при сборке образа песочницы или установке в песочницу):
  скачивает архив релиза из `binary.lock.json`, сверяет sha256, кладёт бинарь в `vendor/gemini-api/`. Не Linux или
  `GEMINI_API_SKIP_FETCH=1` — пропуск. Неудачная загрузка — предупреждение (сервер на каждый вызов отвечает, что бинаря
  нет); несовпавшая сумма — ошибка сборки.
- `binary.lock.json` — репозиторий, версия и суммы архивов для `x86_64` и `arm64`.
- `Options` — ключ, команда бинаря, таймаут.
- `Binary`, `ProcessBinary` — один запуск клиента дочерним процессом (`amphp/process`). Окружение ребёнка своё и
  короткое: ключ, `HOME` и `XDG_CONFIG_HOME` в каталоге вызова, `PATH`, прокси записи (`HTTPS_PROXY`, `HTTP_PROXY`,
  `NO_PROXY`). Потоки читаются до конца, хранится первые 2 МБ каждого. По таймауту процесс снимается.
- `Arguments` — аргументы вызова: любой JSON от модели, каждое значение проверяется там, где читается.
- `Server` — JSON-RPC по строкам: `initialize`, `tools/list`, `tools/call`, `ping`. На вызов — свой временный каталог:
  в `in/` пишутся присланные файлы, клиент работает в каталоге и оставляет в нём результат, файлы результата уходят в
  ответ вложенными ресурсами (`resource` с `blob`), каталог удаляется.
- `mercurius.mcp.json` — план установки в Меркурий: `composer install --no-dev` и запись
  `php ${INSTALL_DIR}/bin/gemini-api-mcp`.

### Инструменты

| Инструмент | Команда клиента | Пометка | Что возвращает |
|---|---|---|---|
| `image` | `image` | не разрушает | файл картинки |
| `speech` | `tts --stdin` | не разрушает | WAV |
| `music` | `music` | нет — спрашивается | файл музыки |
| `video_start` | `video --async` | нет — спрашивается | id операции |
| `video_result` | `video --resume <id> --poll-timeout 60s` | только чтение | файл видео или «не готово» |
| `transcribe` | `transcribe` | только чтение | текст расшифровки |
| `analyze` | `analyze` | только чтение | ответ на вопрос по файлам или видео YouTube |
| `research_start` | `agent run --background --agent …` | нет — спрашивается | id запуска |
| `research_status` | `agent status <id>` | только чтение | состояние и тексты шагов |

Каждый запуск идёт с `--agent-mode --no-interactive --output-format json`: ошибка — один JSON-документ в stderr
(вид, сообщение, подсказки), код выхода 2 — неверные аргументы, 3 — ключ или права.

## Решения

- **Бинарь, а не свои запросы к API.** Официальный клиент уже умеет Interactions API, загрузку файлов, опрос
  длинных операций и классификацию ошибок; свой код здесь — только обвязка. Цена — около 20 МБ в образе песочницы и
  зависимость от формата вывода клиента, поэтому версия закреплена.
- **Версия и сумма закреплены** (`binary.lock.json`): установщик проекта Google суммы не проверяет, поэтому архив
  скачивается своим шагом и сверяется по sha256 из `checksums.txt` релиза.
- **Ключ — в окружении процесса,** не в аргументах; ребёнку передаётся только он и то, без чего клиент не работает.
- **Текст от модели не может стать флагом.** Промпт идёт после `--` или через stdin; короткие значения (модель,
  голос, размер) проверяются по образцу и передаются как `--флаг=значение`; id операции — по образцу; ссылка
  YouTube — только на одно видео YouTube.
- **Имена присланных файлов — слово агента:** от имени берётся последняя часть и безопасные символы; файл пишется
  только в каталог вызова.
- **Пометки — это цена.** Музыка, видео и исследовательский агент пометок не несут: клиент MCP считает такой вызов
  необратимым и спрашивает владельца (решение владельца Меркурия 2026-11-26). Картинка и речь — «не разрушает»,
  чтение — «только чтение».
- **Долгие операции — парой инструментов.** Видео и исследование запускаются и возвращают id; результат читается
  отдельным вызовом. Вызов инструмента не держится дольше таймаута.
- **Пределы.** Файлы на вход — до 10 и до 14 МБ вместе (клиент шлёт локальный файл внутри запроса); файл в ответе —
  до 20 МБ (столько хранит клиент MCP Меркурия), больший называется, но не возвращается; текст в ответе — до 100 КБ.
- **Без ключа сервер запускается** и на каждый вызов отвечает, чего не хватает: так его пробует установка.
- **Картинки на вход `image`** (правка изображения) не поддержаны: как клиент принимает исходную картинку, по коду
  не установлено.

## Что не проверено

Ключа Gemini API нет: сервер проверен на подставном бинаре. 2026-11-26 в песочнице настоящий бинарь v0.5.0 с
`--dry-run` принял все формы вызова, которые строит сервер (`image`, `music`, `video --async`, `video --resume`,
`agent run --background`, `agent status`, `analyze` со ссылкой YouTube), и показал запросы к
`generativelanguage.googleapis.com/v1beta/interactions`. Вживую предстоит проверить: вид JSON-ответов `video
--async`, `agent run --background` и `agent status` (откуда берётся id и текст отчёта), код выхода `video --resume`,
когда видео ещё не готово, и размер настоящих файлов видео против предела 20 МБ.

## Проверки

`composer check` — PHPUnit, PHPStan (max), Psalm (уровень 1); то же в GitHub Actions на PHP 8.2, без сети: бинарь в
CI не скачивается (`GEMINI_API_SKIP_FETCH=1`).
